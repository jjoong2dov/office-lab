# 7편 지시문 — 백업은 복원까지 해 봐야 끝

아래를 AI 코딩 도구에 그대로 준다.

---

**백업**과 **복원**을 만들고, 복원한 결과가 원본과 같은지 **대조**하는 것까지 만든다.
백업 파일이 있다는 것과 복원이 된다는 것은 다르다.

## 먼저 정한 것 (이 예제의 규칙)

- 백업 한 벌 = DB 덤프 + 첨부 파일 묶음 + 목록표(manifest). DB 와 파일은 같은 시점의 것을 한 벌로 다룬다.
- 복원은 **비어 있는 다른 DB 와 다른 파일 폴더**에만 한다. 표가 하나라도 있는 DB, 비어 있지 않은 폴더, 원본과 같은 DB 에는 거부한다.
- 복원 뒤 대조에서 하나라도 다르면 실패(종료 코드 1)다.
- 도구는 PostgreSQL 의 `pg_dump`, `pg_restore` 를 쓴다(PATH 에 있다고 가정). 새 npm 의존성은 더하지 않는다.

## 만들 것

- `scripts/backup.js` — `node scripts/backup.js [백업을 둘 폴더]` (기본 `.data/backups`), `npm run backup`
  - `<폴더>/<시각>/` 아래에 `db.dump`(`pg_dump -Fc`), `files.tar.gz`(파일 폴더), `manifest.json` 을 만든다.
  - `manifest.json`: 만든 시각, 적용된 migration 목록, **표마다 행 수**(`schema_migrations` 와 `sessions` 는 뺀다), **첨부 파일마다 저장 이름·크기·sha256**.
  - 끝나면 백업 폴더 경로를 한 줄로 출력한다.
  - 코드에서도 쓸 수 있게 `export async function backup({ databaseUrl, filesDir, outDir })` → 백업 폴더 경로.
- `scripts/restore.js` — `node scripts/restore.js <백업 폴더> <대상 DATABASE_URL> <대상 파일 폴더>`, `npm run restore -- ...`
  - 위 거부 조건을 먼저 확인한다. 거부하면 아무것도 쓰지 않고 종료 코드 1.
  - `pg_restore` 로 DB 를 넣고 파일 묶음을 푼 뒤, 바로 대조를 돌린다.
  - `export async function restore({ backupDir, databaseUrl, filesDir })`. 거부·실패는 오류를 던진다.
- `scripts/verify-restore.js` — `node scripts/verify-restore.js <백업 폴더> <대상 DATABASE_URL> <대상 파일 폴더>`
  - manifest 와 대상을 비교한다: migration 목록, 표마다 행 수, 파일마다 있는지·크기·sha256, DB 의 `attachments` 행과 파일이 서로 빠짐없이 짝이 맞는지.
  - `export async function verifyRestore({ backupDir, databaseUrl, filesDir })` → `{ ok, problems: [문장...] }`. CLI 는 문제를 한 줄씩 찍고 `ok` 가 아니면 종료 코드 1.
- 세션(`sessions`)은 백업에 넣지 않거나 복원 뒤 비운다. 복원한 시스템에서는 모두 다시 로그인한다.
- README 에 백업·복원 방법과 "복원은 빈 DB 에만" 을 적는다.

기존 확인도 계속 통과해야 한다. 끝나면 `npm run check` 로 확인해 줘.
