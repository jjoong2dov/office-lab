# 3편 지시문 — 퇴사자 로그인은 막고, 작성 기록은 남기기

아래를 AI 코딩 도구에 그대로 준다.

---

직원이 퇴사하면 계정을 지우지 않고 **퇴사 처리**를 한다. 로그인은 막고, 그 사람이 쓴 글과 이력은 남긴다.

## 먼저 정한 것 (이 예제의 규칙)

- 계정 행은 지우지 않는다. 글의 작성자는 계속 그 사람의 내부 번호(`users.id`)로 이어진다.
- 퇴사한 사람의 아이디는 다른 사람에게 다시 주지 않는다(`username` UNIQUE 그대로).
- 퇴사 처리 순간에 **이미 열려 있던 로그인도 끊는다.** 새 로그인만 막는 것으로 끝내지 않는다.
- 개인정보 삭제·익명화는 이 편에서 다루지 않는다.

## 표 (새 migration `migrations/004_offboard.sql`)

- `users` 에 `status text NOT NULL DEFAULT 'active' CHECK (status IN ('active','left'))`, `left_on date NULL` 을 더한다.

## 코드

- `src/org.js` 에 `offboardUser(pool, { userId, onDate })` 를 더한다. 한 트랜잭션에서:
  1. `users.status = 'left'`, `left_on = onDate`(없으면 오늘)
  2. 열린 소속(`org_assignments.ends_on IS NULL`)을 `onDate` 로 닫는다 (`ends_on = onDate`. 2편에서 정한 대로 `ends_on` 당일은 기간에 포함하지 않는다. `left_on` 도 '그날부터 직원이 아닌 날'이다)
  3. 그 사용자의 `sessions` 행을 모두 지운다
  - 이미 퇴사한 사람, 없는 사용자는 오류를 던지고 아무것도 바꾸지 않는다.
- `scripts/offboard.js` : `node scripts/offboard.js <아이디>` 로 위 함수를 부른다.
- 로그인(`POST /login`): `status` 가 `active` 가 아니면 로그인시키지 않는다.
  응답은 비밀번호가 틀렸을 때와 **완전히 같게** 한다(상태 코드와 문구). 퇴사 여부를 바깥에 알려 주지 않는다.
- 요청마다 사용자를 읽는 곳(`src/auth.js` 의 `loadUser`)에서도 `status = 'active'` 를 확인한다.
  세션 행이 어떤 이유로 남아 있어도 퇴사자는 로그인한 사람으로 취급하지 않는다. (이번 편에서는 `src/auth.js` 를 고쳐도 된다)
- 퇴사자가 쓴 글은 그대로 보인다. 글 목록과 글 상세의 작성자 이름 옆에 `퇴사` 딱지(`<span class="tag gray">퇴사</span>`)를 붙인다.
- 부서 이동(`transferUser`)은 퇴사한 사람에게는 오류를 던진다.

기존 확인도 계속 통과해야 한다. 끝나면 `npm run check` 로 확인해 줘.
