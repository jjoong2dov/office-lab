# 1편 지시문 — 부서 게시판

아래를 AI 코딩 도구에 그대로 준다.

---

이 저장소는 가상 회사의 사내 시스템이다. 로그인과 화면 틀은 이미 있다(`src/auth.js`, `src/views.js`).
여기에 **부서 게시판**을 추가해 줘. 기존 로그인·세션 코드는 바꾸지 마.

## 표 (새 migration 파일 `migrations/002_boards.sql`)

- `boards(id, name UNIQUE, department_id NULL → departments.id)`
  `department_id` 가 NULL 이면 전 직원이 보는 게시판이다.
- `posts(id, board_id → boards.id, author_id → users.id, title, body, created_at)`

## 가상 데이터 (`scripts/seed.js`)

- 게시판: `전사 공지`(department_id NULL) 하나, 그리고 부서마다 `<부서 이름> 게시판` 하나.
- 화면이 비어 보이지 않게 게시판마다 글 한두 개.

## 화면과 주소

- `GET /boards` 내가 볼 수 있는 게시판 목록
- `GET /boards/:id` 글 목록 (제목, 작성자 이름, 작성자 소속, 날짜)
- `GET /boards/:id/new` 글쓰기 화면
- `POST /boards/:id/posts` 글 저장. 성공하면 `/posts/<새 글 id>` 로 302
- `GET /posts/:id` 글 상세 (제목, 본문, 작성자 이름·소속, 날짜)
- 왼쪽 메뉴(`src/menu.js`)에 `게시판` 추가

## 권한 — 여기가 핵심이다

1. 판단은 `src/policy.js` 의 함수 하나(`canReadBoard(user, board)`)에 둔다.
   게시판의 `department_id` 가 NULL 이거나 사용자의 부서와 같을 때만 true.
2. **목록, 글 목록, 상세, 글쓰기 화면, 글 저장** 다섯 곳 모두 서버에서 이 함수를 거친다.
   메뉴나 링크를 숨기는 것으로 끝내지 마. 주소를 직접 쳐도 막혀야 한다.
3. 볼 수 없는 게시판·글은 `src/views.js` 의 `notFound(req, res)` 로 답한다(404).
   없는 글과 볼 수 없는 글의 응답이 같아야 한다. 숫자가 아닌 id 도 404.
4. 권한이 없는 글 저장은 DB 에 아무것도 쓰지 않는다.
5. 로그인하지 않은 요청은 전부 `/login` 으로 보낸다(`requireLogin`).
6. 제목과 본문은 화면에 낼 때 `esc()` 를 거친다. 제목은 1~200자, 본문은 1~20000자. 벗어나면 400.

끝나면 `npm run check` 를 돌려서 전부 통과하는지 확인해 줘.
