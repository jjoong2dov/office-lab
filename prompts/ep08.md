# 8편 지시문 — 승인 요청: 요청부터 승인·반려까지

아래를 AI 코딩 도구에 그대로 준다.

---

직원이 **승인 요청**을 올리고, 지정한 **승인자 한 명**이 승인하거나 반려하는 기능을 만든다.
결재선·양식 같은 것은 뒤 시즌에서 한다. 이번에는 요청 하나가 끝까지 처리되는 것만 만든다.

## 먼저 정한 것 (이 예제의 규칙)

- 요청은 올린 사람과 승인자 두 사람만 본다. 같은 부서라도, 시스템 관리자라도 못 본다.
- 올린 뒤에는 제목·본문을 고칠 수 없다. 고치려면 취소하고 새로 올린다.
- 상태는 `pending`(대기) → `approved`(승인) / `rejected`(반려) / `cancelled`(취소) 한 번만 바뀐다. 끝난 요청은 다시 바뀌지 않는다.
- 승인·반려는 승인자만, 취소는 올린 사람만 한다. 자기 요청을 자기가 승인할 수 없다.
- 두 요청이 동시에 와도 하나만 반영된다(화면의 버튼 잠금이 아니라 DB 의 조건으로 막는다).
- 올린 사람의 소속·직급은 올린 당시 값을 남긴다(2편과 같은 이유).

## 표 (새 migration `migrations/008_requests.sql`)

- `requests(id, requester_id → users.id, approver_id → users.id, title, body, requester_department_name, requester_title,
  status text CHECK (status IN ('pending','approved','rejected','cancelled')) DEFAULT 'pending', decision_note text NULL, decided_at timestamptz NULL, created_at)`
- `CHECK (requester_id <> approver_id)`
- 가상 데이터로 요청 두세 건(대기 하나, 승인된 것 하나).

## 화면과 주소 (`src/routes/requests.js`, 왼쪽 메뉴 `승인 요청`)

- `GET /requests` 두 목록: **내가 올린 요청**, **내가 처리할 요청**(대기 중인 것이 위)
- `GET /requests/new` 올리기 화면: 제목, 본문, 승인자 선택(재직 중인 다른 직원)
- `POST /requests` (필드 `title`, `body`, `approver_id`) → `/requests/<id>` 로 302
  - 제목 1~200자, 본문 1~20000자. 승인자가 자기 자신이거나, 없거나, 퇴사한 사람이면 400. 아무것도 저장하지 않는다.
- `GET /requests/:id` 상세: 제목, 본문, 올린 사람(이름·당시 소속·직급), 승인자, 상태, 처리 시각, 처리 의견
  - 올린 사람도 승인자도 아니면 `notFound` (404). 없는 요청과 응답이 같아야 한다.
  - 대기 중일 때만: 승인자에게 승인·반려 폼(의견 입력), 올린 사람에게 취소 버튼
- `POST /requests/:id/approve`, `POST /requests/:id/reject` (필드 `note`, 반려는 의견 필수 1~1000자)
- `POST /requests/:id/cancel`
  - 요청을 볼 수 없는 사람이면 404. 볼 수는 있지만 그 행동을 할 사람이 아니면 403(예: 올린 사람이 승인).
  - 이미 끝난 요청이면 409. 상태는 바뀌지 않는다.
  - 상태 변경은 `UPDATE ... WHERE id = $1 AND status = 'pending'` 한 문장으로 하고, 바뀐 행이 없으면 409 로 답한다.
  - 성공하면 `/requests/:id` 로 302.
- `src/policy.js` 에 `canReadRequest(user, request)`, `canDecideRequest(user, request)`, `canCancelRequest(user, request)` 를 두고 경로는 이것만 부른다.
- 승인자가 퇴사하면 그 사람의 대기 요청은 올린 사람이 취소할 수 있어야 한다(이미 되는 동작이다). 상세에 승인자 이름 옆 `퇴사` 딱지를 붙인다.

## 기록

- `request.create`, `request.read`, `request.approve`, `request.reject`, `request.cancel` 을 6편의 `record` 로 남긴다(resource `request`).
  볼 수 없는 사람의 시도(404·403)는 `denied`. 이미 끝난 요청에 대한 409 는 기록하지 않는다. 제목·본문·의견은 기록에 넣지 않는다.
- 상태 변경의 `ok` 기록은 그 `UPDATE` 와 같은 트랜잭션에 넣는다.

기존 확인도 계속 통과해야 한다. 끝나면 `npm run check` 로 확인해 줘.
