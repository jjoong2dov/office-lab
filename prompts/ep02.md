# 2편 지시문 — 부서를 옮겨도 지난 글의 소속이 남게

아래를 AI 코딩 도구에 그대로 준다.

---

지금은 글의 작성자 소속을 `users.department_id` 에서 읽어 온다. 그래서 직원이 부서를 옮기면 지난 글의 소속까지 바뀐다.
**소속 이력**을 만들고, 글에는 **쓴 당시의 소속**을 남겨 줘.

## 먼저 정한 것 (이 예제의 규칙)

- 한 사람은 한 시점에 한 부서에만 속한다(겸직 없음).
- `users.department_id`, `users.title` 은 "지금 소속"으로 그대로 둔다. 지금 볼 수 있는 게시판은 계속 이 값으로 정한다.
- 부서를 옮기면 옛 부서 게시판은 더 볼 수 없다. 자기가 쓴 글이라도 마찬가지다.
- 과거 글에 찍히는 소속·직급은 쓴 당시의 값이다. 지금 소속으로 다시 계산하지 않는다.

## 표 (새 migration `migrations/003_assignments.sql`)

- `org_assignments(id, user_id → users.id, department_id → departments.id, title, starts_on date, ends_on date NULL)`
  - `ends_on` 이 NULL 이면 지금 소속이다. `ends_on >= starts_on` 을 CHECK 로 건다.
  - 한 사람에게 열린(ends_on IS NULL) 소속은 하나뿐이어야 한다. 부분 UNIQUE 인덱스로 DB 가 막게 한다.
  - 기존 사용자는 지금 소속으로 한 줄씩 채운다(starts_on = 계정 생성일).
- `posts` 에 `author_department_name text NOT NULL`, `author_title text NOT NULL` 을 더한다.
  기존 글은 작성자의 지금 소속·직급으로 채운다. 새 글은 저장하는 순간의 값을 넣는다.

## 코드

- `src/org.js` 에 `transferUser(pool, { userId, departmentId, title, onDate })` 를 만든다.
  - 한 트랜잭션에서: 열린 소속을 `onDate` 전날로 닫고, 새 소속을 `onDate` 부터 열고, `users` 의 지금 소속·직급을 바꾼다.
  - `title` 을 주지 않으면 직급은 그대로다. `onDate` 를 주지 않으면 오늘이다.
  - 같은 부서로 옮기려 하면(직급도 같으면) 오류를 던지고 아무것도 바꾸지 않는다. 없는 사용자·부서도 오류.
  - 중간에 실패하면 전부 되돌린다.
- `scripts/transfer.js` : `node scripts/transfer.js <아이디> <부서 이름> [직급]` 으로 위 함수를 부른다. (관리 화면은 뒤 편에서 만든다)
- `scripts/seed.js` 도 새 표에 맞게 고친다(사용자를 넣을 때 소속 이력 한 줄, 글을 넣을 때 당시 소속).
- 글 목록과 글 상세의 작성자 소속·직급은 `posts` 에 남긴 값으로 보여 준다.
- 홈 화면의 "내 정보" 아래에 **소속 이력** 표를 보여 준다(부서, 직급, 시작일, 종료일. 지금 소속은 종료일 대신 `현재`).

기존 확인(`checks/ep01-board.test.js`)도 계속 통과해야 한다. 끝나면 `npm run check` 로 확인해 줘.
