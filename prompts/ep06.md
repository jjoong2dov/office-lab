# 6편 지시문 — 열람·변경 기록, 무엇을 남길까

아래를 AI 코딩 도구에 그대로 준다.

---

누가 언제 무엇을 했는지 남기는 **기록(감사 기록)** 을 만든다. 허용된 일뿐 아니라 **거부된 시도**도 남긴다.

## 먼저 정한 것 (이 예제의 규칙)

- 남기는 것: 누가(`actor_id`), 무엇을(`action`), 어떤 대상에(`resource_type`, `resource_id`), 결과(`ok`/`denied`), 언제, 어느 요청에서(`request_id`).
- 남기지 않는 것: 글 제목·본문, 파일 이름·내용, 비밀번호, 로그인에 실패한 아이디. 기록 표가 또 하나의 유출 경로가 되지 않게 한다.
  `detail` 에는 꼭 필요한 값만 넣는다(예: 부서 이동의 이전·이후 부서 번호).
- 기록은 **추가만** 한다. 앱이 쓰는 DB 계정으로는 고치거나 지울 수 없게 DB 에서 막는다.
  (DB 관리자 계정까지 막는 것은 아니다. 그건 기록을 다른 곳에 따로 보관하는 문제이고 이 편의 범위 밖이다. README 에 이 한계를 적어 줘.)
- 기록을 보는 권한(`auditor`)은 시스템 관리자(`system_admin`)와 따로다. 시스템 관리자라고 기록을 볼 수 없고, 기록을 본 것도 기록된다.

## 표 (새 migration `migrations/007_audit.sql`)

- `audit_events(id, at timestamptz DEFAULT now(), actor_id NULL → users.id, action text, resource_type text, resource_id bigint NULL, result text CHECK (result IN ('ok','denied')), request_id uuid, detail jsonb DEFAULT '{}')`
- `UPDATE`, `DELETE`, `TRUNCATE` 를 막는 트리거를 건다(예외를 던진다).
- `user_roles.role` 의 CHECK 에 `auditor` 를 더한다.
- 가상 데이터: 감사 담당 `han`(한지민, 경영지원팀, 사원)을 더하고 `auditor` 를 준다.

## 코드

- 요청마다 `req.requestId`(UUID)를 만든다.
- `src/audit.js` 에 `record(db, req, { action, resourceType, resourceId, result, detail })` 를 만든다. `db` 는 pool 이나 트랜잭션 client 둘 다 받는다.
- 기록할 일과 `action` 이름:

| action | 언제 | resource |
|---|---|---|
| `login.ok` / `login.fail` | 로그인 성공 / 실패 (실패는 `actor_id` NULL, 아이디를 남기지 않는다) | `user` / 없음 |
| `post.read` | 글 상세를 열 때. 볼 수 없어서 404 가 나간 경우는 `denied` (그 글이 실제로 있을 때만) | `post` |
| `post.create` | 글 저장. 볼 수 없는 게시판이면 `denied` | `post`(성공) / `board`(거부) |
| `board.read` | 글 목록을 열 때. 거부도 기록 | `board` |
| `board.export` | CSV 내보내기. 거부도 기록 | `board` |
| `attachment.download` | 첨부 내려받기. 거부도 기록 | `attachment` |
| `attachment.create` | 첨부 올리기. 거부(404·403)도 기록 | `attachment`(성공) / `post`(거부) |
| `user.transfer` / `user.offboard` | 관리 화면에서 부서 이동 / 퇴사 처리. 관리자가 아닌 사람의 시도는 `denied` | `user` |
| `audit.read` | 기록 화면을 열 때. 거부도 기록 | 없음 |

- 변경(글 저장, 부서 이동, 퇴사 처리)의 `ok` 기록은 그 변경과 **같은 트랜잭션**에 넣는다. 변경이 되돌려지면 기록도 남지 않는다.
  `denied` 기록은 따로 넣는다(거부됐다는 사실은 남아야 한다).
- `src/policy.js` 에 `canReadAudit(user)` (`auditor` 일 때만 true).
- `GET /audit` 기록 화면(`auditor` 만, 아니면 404): 최근 200건을 최신순으로. 시각, 사람(이름), action, 대상, 결과.
  `?result=denied` 로 거부만, `?action=...` 으로 한 종류만 볼 수 있다. 왼쪽 메뉴 `기록` 은 `auditor` 에게만 보인다.

기존 확인도 계속 통과해야 한다. 끝나면 `npm run check` 로 확인해 줘.
