# 5편 지시문 — 첨부 파일, 직접 주소로도 못 받게

아래를 AI 코딩 도구에 그대로 준다.

---

글에 **첨부 파일**을 붙이고, 게시판 글 목록을 **CSV 로 내보내는** 기능을 만든다.
글을 볼 수 없는 사람은 그 글의 첨부도, 그 게시판의 내보내기도 받을 수 없어야 한다.

## 먼저 정한 것 (이 예제의 규칙)

- 파일 내용은 DB 에 넣지 않는다. 디스크의 파일 폴더에 두고, DB 에는 이름·크기·종류와 저장 이름만 둔다.
- 디스크에 저장하는 이름은 서버가 만든 무작위 값(UUID)이다. 사용자가 올린 파일 이름은 디스크 경로에 쓰지 않는다.
- 파일 폴더는 웹으로 바로 열리는 곳(`public/`)에 두지 않는다. 받는 길은 권한 검사를 거치는 내려받기 주소 하나뿐이다.
- 첨부를 볼 수 있는지는 그 글의 게시판으로 정한다(`canReadBoard`). 새 규칙을 따로 만들지 않는다.
- 첨부는 글쓴이만 붙일 수 있다. 한 번에 파일 하나, 5MB 까지.

## 준비

- `npm install multer` (파일 올리기용, MIT). 다른 의존성은 더하지 않는다.
- `createApp(pool, { filesDir })` 로 파일 폴더를 받는다. 주지 않으면 환경 변수 `FILES_DIR`, 그것도 없으면 `.data/files`. 폴더가 없으면 만든다.

## 표 (새 migration `migrations/006_attachments.sql`)

- `attachments(id, post_id → posts.id, storage_key uuid UNIQUE, original_name text, size_bytes bigint, content_type text, created_at)`

## 화면과 주소

- 글 상세에 첨부 목록(이름, 크기, 내려받기 링크)을 보여 준다. 글쓴이에게는 파일 올리기 폼도 보인다.
- `POST /posts/:id/attachments` (multipart, 파일 필드 이름 `file`) → 저장하고 `/posts/:id` 로 302
  - 글을 볼 수 없으면 404. 볼 수는 있지만 글쓴이가 아니면 403. 둘 다 DB 와 디스크에 아무것도 남기지 않는다.
  - 5MB 를 넘으면 413. 파일이 없으면 400. 이때도 디스크에 파일을 남기지 않는다.
  - multipart 요청은 본문을 읽기 전에는 `_csrf` 를 알 수 없다. `src/auth.js` 의 `checkCsrf` 는 multipart 요청을 건너뛰게 하고,
    이 경로에서 multer 가 본문을 읽은 **뒤에** 같은 검사를 한다. 토큰이 틀리면 403 이고 올라온 파일은 지운다.
- `GET /attachments/:id/download` → 파일을 내려 준다.
  - 그 글의 게시판을 볼 수 없으면 `notFound` (404). 없는 첨부와 응답이 같아야 한다.
  - `Content-Disposition: attachment` 로 원래 이름을 돌려준다(한글 이름은 `filename*=UTF-8''...` 로 인코딩). `X-Content-Type-Options: nosniff` 를 붙인다.
- `GET /boards/:id/export.csv` → 그 게시판 글 목록(번호, 제목, 작성자, 소속, 날짜)을 CSV 로. 게시판을 볼 수 없으면 404.
  - 글 목록 화면에 `CSV 내보내기` 링크를 둔다.
  - 엑셀에서 수식으로 읽히지 않게, 값이 `=`, `+`, `-`, `@` 로 시작하면 앞에 `'` 를 붙인다.

기존 확인도 계속 통과해야 한다. 끝나면 `npm run check` 로 확인해 줘.
